# Embedded DXF filename contract

The real filesystem basename remains the primary name. A valid embedded
`fullFilename` is shown below it, explicitly labeled **Metadata**, in the DXF
File panel, tile caption and opened-file list. Full names wrap in the File
panel and remain available in tooltips where tiles/lists need truncation.
No metadata value controls file paths, ownership, authentication, URLs or HTML.
`configuration`, `sourceId` and `ownerId` are not displayed as user identity.

## Macro writer format

Before the first `0 / SECTION`, emit standard `999` comment pairs:

```text
999
EXCELSIS-DXF-META-V1-BEGIN
999
EXCELSIS-DXF-JSON {"fullFilename":"Original part.SLDPRT","configuration":"Variant 1",
999
EXCELSIS-DXF-JSON "sourceId":"opaque-source","ownerId":"opaque-owner"}
999
EXCELSIS-DXF-META-V1-END
0
SECTION
```

There must be one unambiguous complete block. Join the exact payload of each
`EXCELSIS-DXF-JSON ` line in order, with **no inserted spaces or newlines**,
then parse JSON. Split anywhere in the serialized JSON, including inside a
string; escaping belongs to JSON itself. Do not split a physical comment value
across lines without repeating the `999` code and JSON prefix.

The JSON contains `fullFilename`, `configuration`, `sourceId` and `ownerId`.
Additional macro ownership fields may remain in the same JSON. The reader
extracts the four named display/reference strings and never rewrites or removes
other fields. `fullFilename` is required, a nonempty string up to 4096 characters;
control characters and bidi direction overrides/isolates are rejected. The
reader bounds the preamble to 8192 pairs and concatenated JSON to 256 KiB.
Malformed, incomplete, duplicate or oversized blocks have no display effect;
ordinary DXF geometry still loads. Blocks inside/after drawing sections are
not filename metadata.

`embedded-metadata.mjs` exports `readDxfMetadata(text)` as the small standalone
JavaScript reader and `readDxfMetadataFromPairs(pairs)` for the Viewer parser.
UTF-8/decoded Unicode, BOM and LF/CRLF/CR line endings are supported by the
reader. The existing desktop encoding layer still owns actual file decoding.

## Save and rename

Our parser retains all original group pairs and the serializer retains the
comment values and their order, including unknown ownership data. Existing
DXF serialization may normalize group-code whitespace/line endings to CRLF.
Save, edits, Undo, Save As and sibling transforms do not substitute the disk
basename into metadata. Rename changes only the real disk basename; its
embedded original name remains unchanged and visible underneath.

Autodesk documents that group 999 values are comments, but AutoCAD DXF SAVEAS
may omit them. Do not assume external CAD re-export preserves this block:
[Autodesk group-code reference](https://help.autodesk.com/cloudhelp/2024/ENU/AutoCAD-DXF/files/GUID-3F0380A5-1C15-464D-BC66-2C5F094BCFB9.htm).
No macro writer or real company export was changed/tested by this Viewer update.
The separately delivered portable website ZIP remains version 1.0.0 and is
not regenerated by desktop installer builds.
